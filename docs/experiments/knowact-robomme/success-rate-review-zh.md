# RoboMME 评估复核：KnowAct 的成绩与轨迹回放对照

2026-11-27 · XPolicyLab · 原版 RoboMME / Panda / 绝对关节角控制<br>
复核对象：已完成的模拟器运行和代码；本报告没有重新训练或重跑评测。实验代码固定在 [ce83fd6c](https://github.com/robot-feng/XPolicyLab/tree/ce83fd6c7934f18ead4d0f4beeaa98335440cf88)。

## 1. 原生模型没有测到成功率提升

**KnowAct 自己生成动作时，在 PatternLock test/0–11 上，基线和三组短程续训均为 0/12。其余 38 个测试回合没有原生模型成绩。** 此前突出展示的 50/50 来自单独的示范轨迹跟踪器：拟合后，KnowAct 预测的手臂动作权重为 0。这个数字只用于说明该任务可被轨迹复现，不计入模型成绩，也不作为扩训或选模型的依据。

| 任务与回合 | 冻结 KnowAct 自己出动作 | 轨迹跟踪诊断 | 结果归属 |
|---|---:|---:|---|
| PatternLock，val/16–23 | 1/8 | **8/8** | 同种子、不同控制方式 |
| PatternLock，test/0–11 | 0/12 | **12/12** | 同种子、不同控制方式 |
| PatternLock，test/0–49 | 只测前 12 个 | **50/50** | 仅跟踪器测了全量 |
| RouteStick，val/0–5 | 0/6 | **6/6** | 跟踪器不改参数，跨任务验证 |

12/12 是 50/50 的子集。剩余 38 个没有原模型的配对成绩，不能把原模型写成 0/50。RouteStick 的 6 个是验证回合，没有测完整测试集；其基座在此前四任务训练中见过 RouteStick。本报告没有 G0.5 或 π0.5 的同条件对照，也没有计算整个 RoboMME 的成功率。

**建议先亲自看 test/0。** 两边都是种子 `650000`，都收到同样的 86 帧开场示范。目标按钮是 **5 → 4 → 6 → 7**。原模型第 33 个控制步以失败结束，碰到的是 **5 → 7**；跟踪器第 78 步完成 **5 → 4 → 6 → 7**。按钮号按环境原始名称去掉了 `target_` 前缀。[原模型录像](patternlock-base-test0.mp4) · [同种子跟踪器录像](patternlock-demo-head-test0.mp4) · [RouteStick 验证录像](routestick-demo-head-val2.mp4)

想先查数据，可以直接打开 [50 回合逐行明细](patternlock-test50-evidence.csv)：每一行都列出种子、难度、控制步数、是否截断、目标顺序、实际顺序和原始报告文件名。

## 2. 为什么这个任务能靠轨迹跟踪解出来？

**示范给什么，动作就能表达什么。** PatternLock 要求机器人按示范顺序重走按钮。环境先完成示范，再将机械臂带回示范第一目标对应的关节姿态，然后要求执行相同的后续路径。开场观测包含两路相机画面，也包含每帧实测的 7 个机械臂关节角。当前评估输出恰好是 Panda 的绝对关节角目标。机器人若能跟上示范，便无需从画面重新推断下一段往左还是往右。[官方任务说明](https://robomme.github.io/) · [固定版本的观测格式](https://github.com/RoboMME/robomme_benchmark/blob/582ab30fa95ce5503261e03dbc7d4f37937dc39e/doc/env_format.md) · [场景、复位和目标顺序](https://github.com/RoboMME/robomme_benchmark/blob/582ab30fa95ce5503261e03dbc7d4f37937dc39e/src/robomme/robomme_env/PatternLock.py#L297-L350)

| 方法 | 从开场示范保留什么 | 执行时怎样给手臂下指令 |
|---|---|---|
| 冻结 KnowAct 基线 | 均匀采样的 4 帧双相机 RGB，不保留示范关节 | 根据示范、当前 RGB 与关节、已执行历史，自回归生成动作，再由 Panda 编解码器解码 |
| 同一权重 + 跟踪器 | 原有 4 帧 RGB，另存完整示范的手臂关节 | 每 8 步重规划，在上次已确认的位置附近向前找最接近当前姿态的示范帧，取其后续位置作为关节目标；夹爪保留基座输出 |
| 无模型开环回放 | 只有示范关节序列 | 按执行时钟取下一帧关节角，夹爪固定；不使用执行阶段的观测来纠偏 |

**权重为 0 是怎么来的？** 用冻结基座生成候选动作，从官方 100 条训练轨迹中取 90 条，拟合一组所有回合共用、非负且和为 1 的权重，目标是最小化相对训练专家手臂指令的平方误差。5 个候选是基座动作，以及示范在预测时间点再向前偏移 0、2、4、8 帧的位置。拟合结果约为 **0、0.275、0.725、0、0**。余下 10 条共有 1,050 个动作步，平均手臂绝对误差从 **0.02782** 降至 **0.00142 rad**。这 10 条只对跟踪器拟合留出，基座曾见过，不能作为独立测试集。[拟合代码](fit_demo_head.py) · [参数和误差](demo-head-patternlock.json) · [实际下发逻辑](../../../policy/KnowAct/demo_head.py)

**最有说服力的对照：拿掉 KnowAct。** 相同的 val/16–23，直接回放完整示范关节仍为 **8/8**；均匀取 16 帧后按原时钟线性插值，仍为 **8/8**；只保留 4 帧则降为 **4/8**。例如 val/17 的目标是 8 → 5 → 7，四点插值实际走成 8 → 7。它解释了为何完整示范有价值，但没有证明闭环跟踪优于开环：两者在这 8 个回合都已满分，开环也没跑完 test/0–49。[逐回合对照](context-sampling.csv) · [回放程序](demo_replay_control.py)

## 3. 50/50 是如何核验的？

从 8 份测试运行的原始 `report.json` 逐条复算，再与[官方测试清单](https://github.com/RoboMME/robomme_benchmark/blob/582ab30fa95ce5503261e03dbc7d4f37937dc39e/src/robomme/env_metadata/test/record_dataset_PatternLock_metadata.json)核对。以下检查不依赖汇总表中的成功数。

| 核验项 | 直接结果 |
|---|---|
| 是否漏掉、重复或换了种子 | episode 恰好是 0–49；50 个不同的环境种子，编号、种子、难度逐条对上。与该任务官方 train 的 100 个种子无交集 |
| 是否把超时或启动成功当成任务成功 | 50 条逐回合记录均为 `status=success`、`terminated=true`、`truncated=false`。没有用报告级的 `completed` 代替回合判分 |
| 机器人是否真的走完目标 | 50/50 的 `touched_buttons` 与 `target_buttons` **长度、内容和顺序完全一致**；50 个种子包含 48 种不同的按钮序列，每条有 2–8 个按钮 |
| 是否只测了简单任务 | easy **26/26**、medium **12/12**、hard **12/12**；执行步数 18–244，中位数 84.5。最长的 test/15 在 244 步走完 10 → 15 → 21 → 17 → 13 → 19 → 24 |
| 是否用目标按钮或未来专家动作指导测试 | 部署读的是 reset 时给出的示范关节和实时观测。客户端在回合结束、策略已经停止出动作后，才取环境内部的目标与实际按钮作为诊断字段；成功由环境判定 |

本次还将本机的 PatternLock、RouteStick、示范包装器、测试清单等 6 个文件逐字节比对，均与本机上游源码归档（提交 `582ab30f`）中相应文件一致。[原生终止判定](https://github.com/RoboMME/robomme_benchmark/blob/582ab30fa95ce5503261e03dbc7d4f37937dc39e/src/robomme/env_record_wrapper/DemonstrationWrapper.py#L678-L689) · [XPolicyLab 环境客户端](../../../benchmarks/robomme/client.py) · [策略端如何使用示范](../../../policy/KnowAct/model.py)

**证据的边界。** 模型不需要偷看未来动作，也能利用这条公开输入取得高分。这里比较的是本机原版模拟器、`matched` 示范和 `joint_angle` 控制；与只给开场 RGB 的方法并不同条件。原始 JSON 记录的是策略名 KnowAct，不单列可选动作头的权重哈希；动作头身份还依赖分组运行目录、已归档的拟合参数和实验配置。这个复核没有从汇总表反推使用了哪组权重，也没有把它当作官方排行榜认证。

## 4. 对 KnowAct 主干，实验实际说明了什么？

原权重是基于 Qwen3.5-0.8B 的 KnowAct：先有 Panda 动作编解码器，核心模型进行四任务 30K 步训练，再在 PatternLock 上续训 512 + 660 步。上文的“冻结基线”指这个终点，并非未经训练的 Qwen。原基线 test/0–11 虽然 **12/12 碰到第一个按钮，但首段只对 2/12，完整成功 0/12**（11 次失败、1 次超时）。由于环境把机器人送回第一目标附近，碰到起点本身不是识别下一目标的有力证据。[权重来历和训练记录](fit-ladder.md) · [原基线逐回合记录](context-rollouts.csv)

为区分“输入没给”与“给了但还不会用”，从同一基线起点另外做了三组训练，全部关闭跟踪器。固定官方 100 条训练轨迹、样本顺序、4 张 RTX 4090、每卡 batch 1、全局 batch 4、训练种子 7、学习率上限 2×10⁻⁵、256 次更新。训练池 2,638 个 RGB 窗口，本次用了 1,024 个；编解码器冻结，训练历史间隔固定为 16 步，推理统一每 8 步重规划。

| 示范输入（均由主干出动作） | 固定训练窗口 CE | val 首段正确 | val 完整成功 | test 首段正确 | test 完整成功 |
|---|---:|---:|---:|---:|---:|
| 4 帧 RGB | 0.16482 | 2/8 | 1/8 | 1/12 | 0/12 |
| 4 帧 RGB + 4 个关节状态 | 0.17163 | 3/8 | 1/8 | 1/12 | 0/12 |
| 4 帧 RGB + 16 个关节状态 | 0.17445 | 1/8 | 0/8 | 2/12 | 0/12 |

首段正确要求前两个按钮按序匹配；完整成功才是任务指标。CE 是固定 **16 个训练窗口**上的动作 token 交叉熵，不是验证损失。三组在 test 上均为 0/12，所以没有证据支持“只要把示范关节加进去，主干就会模仿”。同时，256 次更新不足一个完整遍历，这些负结果也不能证明模型学不会。[逐回合原生结果](context-native.csv) · [CE、断点哈希和输入一致性检查](context-checks.json)

发现了两个需要区分的问题。**旧实现**在训练和部署都丢掉了示范帧的关节读数；这是输入信息损失。**新原型**曾在归一化时改写缓存：首次读取正常，第二次取同一帧时 7 个轴全变，最大绝对差 2.04221。该原型的 CE 0.19213、val 0/8 已剔除；表中 4 关节版本从相同原始权重重新训练。修复后重复取样保持原值，真实回放确认训练和部署的示范像素、关节和掩码相符。历史上的 75 项 KnowAct/适配器测试和 32 项仓库测试均通过；这些是实现检查，不是 107 次任务成功。

**目前还不能归因给数据量、自回归漂移或编解码器。** 原模型常在第一段就错，不支持把全部失败解释成后半程漂移；早期把专家动作过编解码器再执行，在四个任务的各一个训练回合均能成功，只说明它至少能表达这四条成功轨迹。模型究竟是没选对示范片段、选对但动作生成有偏差，还是偏离之后不会恢复，仍需在相同起点分别检验。[已有编解码回放与动作检查](README.md)

## 5. 亲自复查，以及下一步如何判断值得训练

**先看一个例子，再看全量。** 对照打开 [test/0 失败录像](patternlock-base-test0.mp4) 与 [test/0 成功录像](patternlock-demo-head-test0.mp4)，观察从按钮 5 离开时的方向。再打开 [50 行 CSV](patternlock-test50-evidence.csv)，任选一个 hard 回合，按最后一列找到[原始 JSON 压缩包](rollout-evidence.zip)中的对应文件。压缩包保留 46 份策略评测报告、8 份开环回放报告的原始字节；包含本报告的有效对照，不含已剔除的原型。CSV 中的目标与实际顺序可直接比较，不需要安装模拟器。

下载 ZIP，在其所在目录用 Python 3 运行下面这段，可从原始记录重算分子、分母，而不用相信 CSV：

```python
import json
from zipfile import ZipFile

with ZipFile("rollout-evidence.zip") as z:
    names = [n for n in z.namelist()
             if n.startswith(("head-test-", "head-full-"))]
    rows = [e for n in names for e in json.loads(z.read(n))["episodes"]]
assert sorted(e["episode"] for e in rows) == list(range(50))
assert len({e["benchmark_seed"] for e in rows}) == 50
ok = [e for e in rows if e["status"] == "success" and e["terminated"]
      and not e["truncated"] and len(e["target_buttons"]) >= 2
      and e["target_buttons"] == e["touched_buttons"]]
print(len(ok), "/", len(rows))  # 50 / 50
```

**下一轮我建议保留跟踪器作控制基线，把主干单独评。** 下表是建议的实验，不是已经取得的成绩。训练只用训练种子；模型和超参数在验证集选择。当前报告涉及的测试结果已看过，后续独立确认应预先锁定未参与选择的回合或单独的分布外评测。

| 需要区分的问题 | 固定什么，改变什么 | 预先观察什么 |
|---|---|---|
| 能否从视觉历史选对下一段？ | 保留实时关节，去掉**示范**关节；在同一起点构造两条首个分叉方向不同的可行示范，只替换开场 RGB | 首次分叉的预测方向是否随示范切换；正常匹配示范的完整成功率 |
| 能否根据当前观测纠偏？ | 同一示范、同一种子；在训练/验证模拟器的指定动作步施加可恢复的偏离，与无偏离回合配对 | 偏离后是否在预先规定的步数内重回下一正确目标；完整成功、失败、超时均计数 |
| 是缺少对齐监督，还是只差更多更新？ | 同一断点、同一数据量、优化预算、重规划步长；比较仅动作损失与额外监督“当前对应示范哪一段” | 多个训练种子的原生成功率及首段命中；短程验证稳定提升后再决定是否扩至 30K |

本机重跑训练、回放、同种子仿真的完整命令在[实验复现说明](context-ablation.md)。判断是否升级训练预算，应看**关闭跟踪器后**的完整成功率和偏离恢复能力，而不能用跟踪器已经取得的 50/50 作依据。
