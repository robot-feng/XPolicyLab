# KnowAct 在 PatternLock 的动作为什么会错

在训练见过的 8 个回合里，给 KnowAct 正确示范、每次决策前的专家画面、关节状态和此前实际执行的专家动作，用它预测的动作拼成轨迹，原生环境只判了 4 次成功。实验把原因定位到了两处：模型在正确输入上的预测本身就会使机械臂按错按钮；用模型自己的动作作为后续预测的条件，又会放大误差。对新布局抓取和其他任务的归因仍需单独验证。[75 次原生回放](failure-audit-replays.csv) · [51 个决策窗口](failure-audit-windows.csv)

## 哪些结果衡量自主能力

同一份权重是 Qwen3.5-0.8B KnowAct、冻结的 Panda ActionCodec。它从原四任务 30K 继续在修正后的 PatternLock 数据上训练 512 + 660 步，最后一轮覆盖全部 100 条训练轨迹。这里用 train/0–7 检查模型能否在见过的状态上执行。权重 SHA-256 为 `41aa0672ef58a2b663e3f4c0c211dbc4355d7abf3adc6e4b2f659fad90aaf6c4`。

| 输入和执行方式 | 种子 | 原生环境完成数 |
| --- | --- | ---: |
| 自主闭环，每 16 步重规划 | train/0–7 | 1/8 |
| 自主闭环，每 16 步重规划 | val/8–15 | 0/8 |
| 自主闭环，每 8 步重规划 | test/0–11 | 0/12 |
| 诊断：原样执行专家动作 | train/0–7 | 8/8 |
| 诊断：专家动作经同一部署编解码器往返 | train/0–7 | 8/8 |
| 诊断：用专家观测和专家历史逐段预测，再执行整条预测 | train/0–7 | 4/8 |

前三行是已有自主评测。后面三行本次重新从原生环境 reset 并执行，不使用示范跟踪头。诊断回放只执行专家记录长度的动作序列；自主闭环可继续重规划直到原生终止或超时，所以两个成功数的差值不能直接分摊给某一类错误。诊断的 4 个未完成回合中，3 个按错按钮，1 个在动作序列用尽时还没走完。[训练与验证逐回合记录](full100-rollouts.csv) · [测试逐回合记录](context-native.csv)

## 哪一段动作使轨迹失败

在每条专家轨迹上，每次只替换连续 16 个控制步（末段可能更短），替换前后均执行原专家命令。替换段由模型在正确的执行前观测与专家历史上生成。每次替换都独立重置环境，51 次中 48 次完成。这个计数描述单段干预，分母中的各窗口来自同一批轨迹。

| 回合 | 环境目标 | 单段干预或累积结果 |
| --- | --- | --- |
| train/0 | 5 → 4 → 3 | 仅替换第 17–32 步后，先触碰 5，随后在第 42 步触碰 3，漏掉 4。仅替换第 33–48 步则在序列末仍只完成 5 → 4。 |
| train/2 | 7 → 3 → 2 → 6 → 1 | 仅替换第 17–32 步后，在第 51 步触碰 2，漏掉 3。 |
| train/3、train/7 | 分别为 16 → 22 → 21 → 17 → 11 和 9 → 8 → 12 → 17 → 22 → 18 | 各自的每一段单独替换都能完成；把这些预测段接起来，两条均按错。 |

CSV 中的 `replace_16` 从零基下标 16 开始，对应上表第 17 个控制步。错误可能在后续专家命令执行期间才触发，因此“漏按第二个按钮”无法单独区分选错目标与轨迹偏离目标。8 条轨迹只替换开头 16 步都能走完，后面的专家命令有机会弥补前段误差。[回合目标、触碰顺序和控制步](failure-audit-replays.csv)

## 历史如何影响动作

每次都给同一开场示范、同一时刻的专家 RGB 和关节状态，只改变执行历史。以下误差在第一次决策之后的 43 个窗口计算，覆盖 616 个控制步，以有效步数加权，对七个手臂关节取平均绝对误差，单位 rad。三组输入都没有当前窗口的未来动作。编解码对照单独使用专家未来动作测量重建误差。

| 执行历史条件 | 关节 MAE |
| --- | ---: |
| 专家执行历史 | 0.01160 |
| 保留当前专家观测，历史动作换成模型自己预测的动作 | 0.01742 |
| 清空执行历史，每轮仍提供同一开场示范 | 0.02569 |
| 专家动作直接编码再解码 | 0.00445 |

换成自身动作历史时误差上升约 50%，去掉整个执行历史后误差更大。“自身历史”组保持了专家画面和关节状态，这个干预专门测历史动作的效应，实际闭环还会改变后续画面与状态。

同一次规划内部也能隔离误差传播。8 条轨迹的 51 个窗口里，动作第一块的可变 token 命中 645/714。对后续块，前面的块由模型生成时命中 931/1122（83.0%）；逐块提供正确的专家前缀时命中 1074/1122（95.7%）。两组共用同一执行历史，每个位置都排除了语法强制固定的 token。过去报告的 95.91% 则是全训练集、含固定语法位、给专家前缀的准确率，统计口径与自主执行不同。[窗口明细](failure-audit-windows.csv) · [原训练统计](fit-ladder.md)

## 训练与推理实现核对到哪里

历史四任务 30K 确认有两处数据问题。训练缺少开场示范，且动作标签配到了执行这条动作之后的图像与关节状态。后续 PatternLock 数据恢复开场 4 帧 RGB，以 reset 后的真实初始观测监督首个动作，之后每条动作配执行前观测。[原始时序测量与编解码对照](README.md) · [修复与验收](patternlock-pilot.md)

这次把修正后的同一权重置于评估模式，在 BF16 下对比训练用整序列前向与部署用增量缓存前向。两端都给真实专家动作前缀，并用部署相同的合法动作范围与联合约束选 token。train/0–7 的头两次决策共 16 处，输入至当前观测结尾的 token ID 和长度 16/16 完全相同。576 个可变动作位置中两条路径的选择相同 572 个；相比专家目标，离线路径命中 512 个，部署路径命中 513 个。4 处分歧都在首次决策，尚未定位其来源。这里没有比较长历史的缓存、训练时的梯度或自主轨迹上的全部输入。[逐决策数字](failure-audit-windows.csv) · [实际调用两条路径的脚本](probe_token_parity.py)

这批种子上，原样专家动作和经过部署编解码器的专家动作都能完成；系统性关节映射错位、动作表示精度不足或早期推理路径整体偏移，均与这组结果不符。能够确定的是当前权重的动作选择与误差传播都影响执行。示范采样是否遗漏转折、视觉是否能识别下一目标、对偏离状态的监督是否充分、基模容量是否限制效果，尚无独立对照足以定责。

## 复现

从仓库根目录开始，按 [PatternLock 环境与数据准备](patternlock-pilot.md) 设置 `EXP`、`PILOT`、`KNOWACT_PYTHON`、`ROBOMME_PYTHON`、`KNOWACT_OUTPUT_ROOT` 和 `KNOWACT_ROBOMME_DATA`。需要已修正的 preaction 缓存、上述权重和原生仿真资源。

```bash
export PYTHONPATH="$EXP:$PWD/policy/KnowAct/G05/src:$PWD/policy/KnowAct/G05:$PWD:$PWD/..${PYTHONPATH:+:$PYTHONPATH}"
export KNOWACT_REPLAN_STEPS=16 KNOWACT_KEEP_HISTORY=true
unset KNOWACT_DEMO_HEAD
D="$PILOT/cause-audit"
WEIGHTS="$KNOWACT_OUTPUT_ROOT/RoboMME-knowact-pattern-full100-panda-joint-7/last.pt"
mkdir -p "$D/offline" "$D/grafts"
EPISODES=(0 1 2 3 4 5 6 7)
"$KNOWACT_PYTHON" "$EXP/probe_token_parity.py" --weights "$WEIGHTS" --data "$KNOWACT_ROBOMME_DATA" \
  --episodes "${EPISODES[@]}" --output "$D/token-parity.json"
"$KNOWACT_PYTHON" "$EXP/probe_history.py" --weights "$WEIGHTS" --data "$KNOWACT_ROBOMME_DATA" \
  --episodes "${EPISODES[@]}" --out "$D/offline"
"$ROBOMME_PYTHON" "$EXP/trace_patternlock.py" --data "$KNOWACT_ROBOMME_DATA" --split train \
  --episodes "${EPISODES[@]}" --out "$D/grafts"
"$ROBOMME_PYTHON" "$EXP/trace_patternlock.py" --data "$KNOWACT_ROBOMME_DATA" --split train \
  --episodes "${EPISODES[@]}" --out "$D/grafts" --predictions "$D/offline"
```

## 下一轮怎样分辨原因

优先回答两个尚未区分的问题。在相同初始布局上替换成另一条有效示范，使它要求前往不同的第二个按钮，观察模型的第一段是否随示范改变。随后固定目标，在模型真实偏离的位置由专家重新规划，比较模型能否从新位置回到同一目标。这两个实验分别检验读懂目标和纠正运动误差的能力。

训练对照可从同一权重出发，固定动作编解码器、更新步数与总窗口数，一组使用普通示范，一组等量加入来自训练种子的专家接管样本。已有 5 次成功接管、360 个动作；评价时两组都只接收正常的示范、实时观测和自己的历史，记录独立验证种子的首段正确数、偏离后恢复数和整回合成功数。检验 MoveCube 时，应从执行场景中方块的实际位置判断抓取，并单独报告布局改变后的结果。[已有接管数据与固定对照方案](fit-ladder.md)
