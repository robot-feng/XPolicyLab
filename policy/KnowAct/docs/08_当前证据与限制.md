# 08｜当前证据、历史结果与限制

## 1. 当前发布包含什么

- 基于用户上传 XPolicyLab 快照的独立 `policy/KnowAct`。
- vendored G0.5 源码副本及其许可证 / NOTICE。
- Native Context 训练与推理实现。
- 原生 `G05Policy.generate_text()` / `generate_action()` 的共享状态路径。
- BAR16 与原 ActionCodec 的生成/解码路径。
- 已执行动作前缀回执、hold-pad 重编码和 chunk-boundary replanning。
- XPolicyLab Adapter、deploy、train/eval shell 和成对比较脚本。
- 73 项 CPU 源码回归测试和 V5–V7 历史实验记录。

## 2. 本次整理后新增的内容

- 重写 `compare.py`：官方 RoboDojo G05 默认 action source 改为 FM；支持显式选择 G05-AR；G05-MEM 可单独指定 action source；明确比较执行间隔；严格 paired CSV 校验。
- 扩展比较脚本单元测试。
- 强化 `preflight.py`：检查 Python 3.10、CUDA、XPL/G05 源码、资产路径和 LeRobot 目录结构；仍仅为存在性检查。
- 训练模式非法值现在明确报错；`native/context/knowact` 映射到 Native AR 模式。
- 新增中文代码地图、数据语义、训练、推理、闭环、实验和复现文档。
- 清除 Python bytecode / `__pycache__`，保留原始 JSON/CSV/NPY/log 实验记录。

## 3. V7 关键证据（均非正式预训练模型 benchmark）

### 3.1 计算与源码回归

- V7 之前的源码回归：69/69 CPU tests passed。
- 本次整理后，比较脚本新增测试并重新运行：73/73 CPU tests passed。
- 测试包括真实 G05 模型数学路径的小尺寸实例、原生 ActionCodec 小配置、BAR 标签、GDN 状态、上下文 replay、执行回执、XPL adapter 模拟 IO 和 paired scoring。
- 没有官方预训练权重，没有 GPU，没有真实 RoboDojo 仿真 episode。

### 3.2 训练 / 生成诊断

V7 记录了三个种子的重复场景诊断：延长训练后部分动作码 teacher-forcing 与 free-running 准确率上升，但完整动作序列 exact match 仍不稳定。此实验使用小尺寸真实 G05Policy 类、随机初始化权重和测试文本映射；不是官方 Qwen3.5-2B 预训练模型结果。

### 3.3 ICL 诊断

V7 的 held-out permutation 实验中，完整历史模型的夹爪规则准确率约为33.33%，同一模型清空历史后也是33.33%，与随机选择参考相同。该结果不支持“已经学会 ICL”。当前真实数据管线也只采样同 Episode 历史，不做跨 Episode demonstration sampling。

### 3.4 动作码依赖

- 原生 rule tokenizer 的两种合法夹爪模式可能形成多个 grammar-valid 的组合；语法约束不等于任务意图正确。
- 小型随机 FSQ Codec 的双峰独立边缘分布计算说明并行块可能出现联合分布缺陷；这是构造诊断，不是正式预训练 RVQ 的经验概率。
- `audit_action_codes.py` 需要来自相同可用上下文的成对专家替代动作。不能把任意两条未配对轨迹当成多峰分布样本。

### 3.5 ActionCodec 因果性

V7 小型原生 Codec prefix perturbation 测试中，改变后部合法神经码会影响前部连续动作。该结果说明当前测试配置不支持安全的部分解码执行。正式预训练 ActionCodec 必须重新测试；在通过前，KnowAct 采用完整解码后再执行前缀。

## 4. 当前最重要的限制

1. 正式 G05 预训练 checkpoint / HF processor / ActionCodec 尚未在当前运行环境完成加载回归。
2. 当前执行环境无 CUDA；BF16 / FlashAttention / FLA GPU 数值和性能未验收。
3. 当前多轮训练历史只来自同一个 Episode，不是跨 Episode ICL。
4. 当前 validation DataLoader 仍走原单轮路径，多轮 validation 未接通。
5. 当前 Native Context 只支持 RoboDojo `arx_x5` joint 配置下的特定数据处理约束。
6. 当前只支持 AR/BAR16，不支持 FM Native Context。
7. BAR16 联合动作分布尚未在正式预训练模型和真实任务上证明。
8. 原 ActionCodec 尚未证明严格因果前缀解码，因此不能边生成局部 Token 边执行。
9. 闭环仅在动作 chunk 边界接收回执和重规划；没有 mid-chunk async interrupt。
10. `compare.py` 生成命令、manifest 和 paired CSV 统计；不自动从仿真日志抽取 success。
11. 尚无正式同预算 RoboDojo G05 vs KnowAct 成绩，因此不能声称 KnowAct 已超过 G05。

## 5. 结果分级建议

今后所有实验结果必须标记以下等级之一：

- **S0 Static / Unit**：语法、shape、mask、codec、cache 单元测试。
- **S1 Small real-source**：真实 G05 类与真实代码路径，但小尺寸/随机初始化/测试 fixture。
- **S2 Pretrained offline**：正式预训练权重、真实数据样本、无闭环仿真。
- **S3 Simulator**：真实 RoboDojo 环境的闭环 rollout。
- **S4 Physical robot**：实体机器人实验。

S0/S1 通过不代表 S2/S3/S4 通过。正式模型提升结论至少需要 S3 的配对评测。
