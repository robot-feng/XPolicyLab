# 07｜正式验收门槛与统计规范

## 1. 分阶段 Gate

| Gate | 名称 | 必须完成 | 不通过时 |
|---|---|---|---|
| G0 | Source / Asset | Python、依赖、checkpoint、processor、codec、dataset 版本匹配 | 不启动训练 |
| G1 | Numerical Equivalence | 单轮兼容、Full/Incremental、MRoPE、GDN、BF16/GPU 回归 | 修复计算路径 |
| G2 | Data Integrity | Episode 边界、时间偏移、动作前缀、normalization、无未来泄漏 | 修复数据管线 |
| G3 | Training Smoke | 1–10 step forward/backward/optimizer、checkpoint save/load | 不扩大预算 |
| G4 | Controlled Post-training | Single vs Context，匹配预算、多训练 seed | 不做性能结论 |
| G5 | Simulator | paired task/seed/episode 的闭环成功率与失败分类 | 分析失败类别 |
| G6 | Final Claim | 同预算对照、置信区间、所有核心任务和消融齐全 | 不声称超越 G05 |

## 2. 训练实验必须同时匹配的预算

至少记录并尽量匹配：

- 初始化 checkpoint 和参数更新范围（全量 / 部分冻结）。
- 训练数据 split、episode 数量、采样分布。
- 有效监督 Token 数（不仅是 optimizer steps）。
- 输入 Token 数、上下文轮数分布、视觉帧数。
- batch size、gradient accumulation、effective batch size。
- optimizer、learning rate、warmup、weight decay、gradient clipping。
- optimizer updates、总训练时长、GPU hours、峰值显存。

Native Context 输入更多历史 Token，单纯“相同步数”不代表相同计算预算。至少报告固定更新数和固定 GPU-hours 两种视角；若算力有限，先固定更新数并报告 token / FLOPs 差异。

## 3. 随机种子层级

不要混淆：

1. **Training seed**：模型初始化之外的采样、dropout、数据顺序。
2. **Evaluation seed**：环境随机化和 task initial state。
3. **Episode ID**：同一 task/seed 下具体 episode 实例。

同一对照组必须使用相同 evaluation seed 和 episode ID，形成 paired comparison。训练 seed 与 evaluation seed 不必相同，但都要写入 manifest。

## 4. 统计报告

对每个模型至少报告：

- 总 episode 数、成功数、成功率。
- 每个 task 的成功率，不只报告 macro/micro 平均。
- 相对 G05 的 paired success delta。
- 以 `(task, evaluation_seed)` 为 cluster 的 bootstrap 区间。
- 训练 seed 间均值和标准差。
- 失败类型的频数和代表 episode。

当前 `compare.py` 的 cluster bootstrap 是描述性统计；task/seed cluster 太少时区间不稳定。正式论文分析应根据任务数、seed 数和数据结构做统计功效规划，必要时使用配对二项检验 / mixed-effects model，并在实验前预注册。

## 5. 防止数据泄漏

- 训练、验证、测试按 episode / task instance / rule instance 分组，不按相邻帧随机切分。
- 同一 Episode 历史不能跨越 episode boundary。
- Query 的 GT 动作、未来观测、未执行动作后缀不能进入上下文。
- Demonstration ICL 的 demo/query 规则实例必须明确分组；held-out rule 不得在训练中出现。
- 真实执行回执只能记录环境确认已应用的步数；不能把模型预测计划的全部 horizon 伪装成执行历史。
- 历史模态消融必须重建 GDN / KV Cache；只改 Attention mask 不会删除 GDN 已累积的信息。

## 6. 成功标准与非劣标准

在先导实验后、正式测试前冻结阈值。建议至少包括：

- 常规操作对 G05 的非劣界限。
- Memory / ICL 任务的最小实际提升。
- 必要历史反事实正确率。
- 无关历史不变性。
- 扰动恢复率与恢复代价。
- 连续动作合法性、碰撞率、夹爪事件准确率。
- P50 / P95 latency 和显存预算。

不要在观察测试集结果后再调整阈值。不要用 Toy exact match 替代真实任务成功率。

## 7. 何时保留新设计

每个新增机制必须回答：

1. 它修复了哪一个已复现的失败？
2. 对应的最小对照是什么？
3. 在至少多个训练 seed、多个 task 上是否稳定？
4. 是否增加参数、显存、延迟或工程复杂度？
5. 更简单的原生 G0.5 机制是否已足够？

如果没有稳定、可重复、可归因的收益，就删除该机制。
