# 02｜数据语义与训练实现

## 1. 当前数据来源和支持范围

当前 Native Episode 采样接在 G0.5 `MixtureLerobotDataset.__getitem__` 上。先由原数据集选择当前帧，再从当前帧所属的 inner dataset 读取同一 Episode 的历史帧。

**重要：目前不是跨 Episode 示范 ICL。** `completed_history()` 只在当前样本所在 Episode 的绝对索引范围内采样历史。V7 的 held-out mapping ICL 实验是小尺寸合成诊断，不代表真实 RoboDojo 数据管线已具备跨 Episode demonstration sampling。

## 2. 历史采样规则

相关配置：

```yaml
model:
  model_arch:
    native_context: true
    native_context_turns: 4
    native_replan_steps: 16
    native_context_max_tokens: 16384
```

含义：

- `native_context_turns=4`：每个当前样本随机选择 1 到 4 个可用历史轮次（不是固定总轮数）。
- `native_replan_steps=16`：历史动作只承认已执行的前 16 个控制步。
- 当前动作预测仍是原配置的 32 步 horizon。
- `native_context_max_tokens=16384`：每个完整 Episode 序列的硬 token 上限。

历史索引通过 `history_indices(start, end, current, stride, turns)` 计算。边界限制在当前 Episode 的 `[from, to)`，并受数据集 `_start_idx` / `_end_idx` 限制，不跨 Episode 或 split。

## 3. 为什么要 hold-pad

原 G0.5 ActionCodec 使用固定 horizon。假设模型预测 32 步，但部署只执行前 16 步：

- 前 16 步是已确认应用的命令。
- 后 16 步尚未执行，不能作为历史事实输入。
- 原 Codec 仍需要固定长度输入，因此用第 16 步动作重复填充后半段。
- 这段填充仅是表示适配，不会下发给机器人执行，也不声称是测量到的真实轨迹。

`hold_pad(action, count)` 的不变式：

1. `action[:count]` 保持不变。
2. `action[count:]` 全部复制 `action[count-1]`。
3. 修改原始动作的未执行后缀，不得改变 hold-pad 结果。
4. `count` 必须是 1..horizon；0 步执行由 runtime 单独处理，不编码动作历史。

## 4. 数据管线的硬约束

`completed_history()` 会拒绝当前未验证的处理配置：

| 条件 | 要求 | 原因 |
|---|---|---|
| `obs_size` | 1 | 当前实现按独立当前观测事件编码 |
| `past_action_size` | 0 | 避免旧式 past-action 输入与 Native Context 重复 |
| 图像/状态正时间偏移 | 不允许 | 禁止未来观测泄漏 |
| action `time_offset` | 必须为 0 | 让动作目标和事件时间语义对齐 |
| `model_fps` 与 `fps` | 相等 | `replan_steps` 才对应真实控制步数 |
| action transforms | 不允许 | 历史命令必须与当前动作采用同一 pointwise 语义 |
| stepwise action normalization | 不允许 | hold-pad 后编码需保持固定 pointwise 归一化 |
| action filter | 必须为 DummyActionFilter | 避免历史前缀经过不一致过滤 |

这组约束目前只针对 RoboDojo `arx_x5` joint 配置验证。换数据集、频率、归一化、ActionCodec 或本体时，先写数据对齐测试，不要绕过 guard。

## 5. 历史轮次的监督语义

在 `collate_episodes()` 中：

- 在当前默认 `native_replan_steps=16` 的 executed-history 模式下，历史轮次带有 `_native_executed_steps`，Collate 将其标记为 `supervise=False`，`native.train()` 中将 labels 全部设为 `-100`。
- 当前轮次保留原始 G05 Processor / BARBuilder 产生的 labels。
- 如果显式设置 `native_replan_steps=0`，历史动作不执行前缀截取；当前 Collate 不会自动把这些历史轮次标记为 context-only，因此可能参与多位置监督。该模式不是当前 RoboDojo 默认配置，使用前必须单独验证监督语义。
- 当前轮次前的历史执行回执通过原有 command 文本槽位追加，不新增 token embedding 或 vocabulary。
- 只对当前目标计算原生 CE；多轮历史是条件上下文。

V7 的 `native_mask_fixed_action_targets` 是可选诊断开关，默认关闭。现有合成实验没有证明它稳定改善 ICL，因此正式训练不要默认打开。

## 6. Loss 与训练实现

`native.train()`：

1. 对 Episode 中每轮样本调用原 `InputPreprocessor`。
2. 使用原 `encode_context_segment()` 编码视觉、语言和 proprio。
3. 拼接 embedding、mask、labels 和 image-grid metadata。
4. 调用一次 `G05ModelQwen35.forward_context()` 计算完整序列。
5. 调用原 `ARHelper.cal_ce_loss()`。
6. 按有效监督 Token 数汇总 Episode loss。

没有新增 memory loss、contrastive loss、ICL head 或额外动作头。

## 7. 目前的训练/验证不对称（必须注意）

在 `G05/scripts/finetune.py` 中，Native `collate_episodes` 当前只接入 `train_dataloader`。`eval_dataloader` 仍使用原始单轮 `action_collate_fn`。因此：

- 当前 Validation Loss / Validation Accuracy 不代表多轮 Native Context 验证性能。
- 不能用现有 val loss 证明多轮历史有效或无效。
- 正式对比前应补充独立的 Native Validation Collate，或者至少增加独立多轮验证脚本。
- 验证历史必须使用 validation split 内部的同 Episode 历史，不能跨 train/val split。

## 8. 当前数据能力与下一步 ICL 数据能力的区别

| 能力 | 当前是否实现 | 说明 |
|---|---|---|
| 同 Episode 历史上下文 | 是 | 已接入 `MixtureLerobotDataset` |
| 已执行动作前缀历史 | 是 | 16 步前缀 + hold-pad |
| 真实执行回执 | 是（runtime） | 回执表示命令应用步数，不是测量轨迹 |
| 跨 Episode demonstration sampling | 否 | 需要独立的 episode sampler / dataset wrapper |
| held-out task rule ICL | 否（真实数据管线） | 仅有小尺寸合成诊断 |
| demonstration/query 的严格 split | 否 | 正式 ICL 实验前必须设计 |
| 多轮 validation | 否 | 需补齐后再报告多轮验证指标 |

## 9. 正式训练前的数据审计

至少保存以下信息：

- 数据集版本、LeRobot schema 版本、episode 数量和 split 清单。
- 每个 task / episode 的实际 FPS、action horizon、obs offsets。
- 归一化统计文件路径和 hash。
- ActionCodec checkpoint hash、配置、block size、RVQ 层数、rule tokenizer 配置。
- 历史采样的 episode ID、绝对 frame index、执行步数、PAD mask。
- 每个 Episode 的有效监督 Token 数、历史 Token 数、总 Token 数。
- train/validation/test 的 episode 不重叠证明。
