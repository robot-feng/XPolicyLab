# 04｜正式实验矩阵与消融计划

## 1. 总原则

Toy 实验已完成其主要用途：定位实现 bug、构造可控反例、验证因果约束和执行状态事务。下一阶段不再以扩充 Toy 数量作为模型进展指标，应以正式 G0.5 权重、真实 ActionCodec、真实 LeRobot Episode 和 RoboDojo rollout 为主。

所有实验必须记录：

- 源码版本与 `git diff` / commit。
- checkpoint 文件 hash、初始化来源、训练 seed。
- ActionCodec、HF processor、normalization stats 的 hash。
- 数据集版本、split、episode 清单。
- task、env config、embodiment、FPS、action horizon、执行间隔。
- batch size、gradient accumulation、effective batch、训练 steps、监督 Token 数、GPU hours。
- evaluation seed、episode ID、任务是否配对、实际执行步数。

## 2. Experiment 0：正式预训练权重回归（先做，不训练）

### 目的

证明 KnowAct vendored G0.5 能正确加载官方权重、Processor 和 ActionCodec，并确认单轮 legacy 行为与原版 G05 的差异可解释。

### 资产

从 XPolicyLab G05 README 对应的官方 RoboDojo 训练资产准备：

```text
pretrained/
├── checkpoints/model_state_dict.pt
├── hf_processor/
└── action_tokenizer_hf/
```

另需真实 RoboDojo LeRobot v3 数据集，至少有 `meta/`、`data/`、`videos/`。

### 检查

1. checkpoint missing / unexpected keys；逐层确认 Vision、VLM、GDN、Action Expert、LM Head。
2. Processor 和 Tokenizer 版本与 checkpoint 配置匹配。
3. ActionCodec encode → decode，记录 reconstruction error、NaN、shape 和 absent keys。
4. G05 原版与 KnowAct legacy 路径对相同样本的 logits / action 输出。
5. Full forward 与 incremental append 的 hidden / logits / position / cache 误差。
6. BF16 / FP32，FlashAttention / SDPA / FLA backend 的数值回归。
7. 1、4、8、16 轮上下文的峰值显存、P50/P95 latency、token 数。

### 通过条件

- checkpoint / processor / codec 对应关系明确；无未经解释的关键权重缺失。
- 单轮兼容差异在明确容差内；差异必须能归因到指定修复。
- 位置布局一致；FP32 / BF16 的输出差异在预设阈值内。
- ActionCodec 无非法输出、NaN 或错误动作维度。
- GPU smoke test 完成后再启动正式训练。

## 3. Experiment 1：Native Context 的真实收益

### 模型组

| ID | 训练方式 | 推理历史 | 目的 |
|---|---|---|---|
| G05-FM | 官方 RoboDojo FM checkpoint | 按官方配置 | 外部官方基线 |
| G05-MEM | 官方/匹配的 G05 memory checkpoint | 按该 checkpoint 的训练 offsets | 原生视觉记忆基线 |
| KA-Single | 同一 G05 预训练基座、BAR16、单轮训练 | 当前观测 | 控制模型/训练变化 |
| KA-Context | 同一基座、BAR16、Native same-episode context 训练 | 完整上下文 | 核心 KnowAct |
| KA-Reset | 与 KA-Context 完全相同 checkpoint | 每轮清空历史 | 测试推理时历史的贡献 |
| KA-Current | 独立单轮训练 checkpoint | 每轮清空历史 | 测试训练期历史是否有贡献 |

注意：G05-FM 与 KnowAct-AR 的动作生成范式不同，适合比较实际策略性能；若要单独归因于 Native Context，必须同时比较 KA-Single、KA-Context、KA-Reset。

### 任务

优先选择 RoboDojo 中具有历史依赖、遮挡、计数、顺序和长程操作的任务，同时保留 Stack Bowls、Insert Tubes 等常规/精细操作任务作为能力回归。

### 反事实测试

对每个真实评测实例构造配对干预：

- 必要历史改变、当前观测相同：模型行为应随历史改变。
- 历史相同、当前观测改变：模型应根据当前观测纠错。
- 无关历史改变、有效信息相同：模型行为应保持稳定。
- reset ablation：同一 checkpoint 清空历史后性能应下降于必要历史任务，但不应在常规单轮任务中明显退化。

### 模态消融

同一 checkpoint 分别去掉历史视觉、语言、状态、动作；每次都必须从被干预后的完整上下文重建 Cache，不能只屏蔽当前 Attention，因为 GDN 已经吸收历史。

### 指标

任务成功率、paired success delta、置信区间、目标选择准确率、历史事件召回准确率、必要历史反事实准确率、无关历史不变性、上下文长度、P50/P95 latency、峰值显存、失败类别。

## 4. Experiment 2：真正的示范式 ICL（当前数据管线尚未实现）

当前 `native_episodes.py` 只采样同一 Episode 历史，不是跨 Episode ICL。正式 ICL 之前需要先设计 demonstration/query sampler：

1. 每个 task episode 或规则实例有明确 `demo_pool` 和 `query_pool`。
2. demo 和 query 按任务实例 / 规则分组隔离，防止同一目标泄漏。
3. Query 当前图像不能直接揭示规则；正确动作必须依赖示范。
4. Demo 可以来自不同 episode，但必须满足相同机器人本体、Processor、归一化和动作语义；跨本体示范另设实验。
5. Demo action 必须是实际专家执行结果，或有明确定义的可验证示范；不能把未来 GT 伪装成已执行反馈。

### Shot 数量

Zero-shot / 1-shot / 2-shot / 4-shot；另测 demo 顺序置换、无关 demo、矛盾 demo、规则交换、未见组合规则、未见物体和未见布局。

### 监督消融

- A：现有语言监督 + 当前动作监督。
- B：示范上下文 + 当前动作监督。
- C：增加简短规则描述语言监督 + 当前动作监督。
- D：增加历史状态 / 执行结果语言描述 + 当前动作监督。

仍使用同一个 LM Head 和 CE。报告有效监督 Token 数与训练 compute；不要只比较训练 steps。

### 关键判据

同一模型权重、同一 query、交换 demonstration 后，动作必须按示范规则变化；清空 demo 后性能应下降；无关 demo 不应明显改变动作。

## 5. Experiment 3：Structured Action Autoregression

### 先做真实 Codec audit，不先改生成顺序

从真实专家数据导出同一任务条件下两条或多条不同但都合法的动作轨迹，使用正式 ActionCodec 编码。`audit_action_codes.py` 当前输入 `.npy` shape 为 `[N, 2, L]`，表示 N 组配对专家替代动作；两条动作必须对应相同可用上下文，不得把任意不配对轨迹当成合法多峰样本。

记录：

- Codec collisions / 完全相同码序列。
- 首个分歧 Token、首个分歧 BAR block。
- 每个 block 内不同 code 位置数。
- RVQ level / group marker / gripper rule 的位置。
- 条件互信息或成对依赖统计（需对相同上下文配对采样）。
- Codec reconstruction 和 oracle rollout success。

当前脚本的 `2^(1-d)` 是等权双峰、独立边缘采样的理论诊断，不是预训练模型实测联合动作概率。不能把它作为 BAR16 的实际成功率。

### 生成粒度对照

AR1 / BAR8 / BAR16 / BAR32 / Codec-aware ordering。每种布局必须重新训练或有合法的 layout conversion；禁止只在推理时修改已有 checkpoint block size。所有组匹配初始化、数据、监督 Token 数、优化更新、计算预算，并报告有效输出 Token。

### 指标

Teacher-forcing token accuracy / CE、free-running token accuracy、完整动作码 exact match、rule validity、motion validity、mode coverage、collision、gripper event accuracy、joint/EEF error、task success、P50/P95 latency。

只有当真实任务成功率和动作质量稳定提升且延迟收益成立，才保留复杂的生成顺序。否则保持原生 BAR16。

## 6. Experiment 4：Continuous Closed-loop

### 执行间隔矩阵

固定预测 horizon=32，分别训练并评测 H32-E32、H32-E16、H32-E8、H32-E4。训练 stride 与部署 stride 必须匹配；不匹配的实验只能标为 stress test。

### 扰动

- 目标位置变化。
- 抓取失败 / 物体滑移。
- 视觉遮挡。
- 部分执行 / 0 步执行。
- 额外暂停和无效动作。
- 任务过程中更新语言指令。
- 模型 proposal 与真实环境状态不一致。

### 指标

任务成功率、扰动恢复率、恢复所需重规划次数、额外控制步数、恢复时间、重复错误率、碰撞率、未执行动作泄漏、真实观测与预测状态误差。

当前回执仅确认命令应用步数；必须在仿真日志中同时记录实际状态变化，不能把命令回执当作测量轨迹。

## 7. 随机种子与样本量

先导实验：3 个训练 seeds（建议 11/22/33），每 task/seed 10–20 episodes；用于估计方差与修复协议。

正式实验：建议至少 3–5 个训练 seeds、每 task/seed 50–100 个 paired episodes，具体由先导方差和算力预算决定。所有模型使用相同 task、seed、episode ID、环境初始状态、执行间隔和评测终止条件。

同一个 task/seed 下的 episode 成对比较；统计时同时报告逐任务结果和跨 task/seed 的 cluster-bootstrap 区间。少量 cluster 的区间仅作描述，不做强结论。

## 8. 预注册的通过门槛（先导后冻结）

建议正式运行前冻结以下门槛，避免看结果后再修改：

- 常规任务相对 G05 非劣界限，例如不低于 -3 个百分点。
- 历史依赖任务相对匹配基线的最小提升，例如 +10–15 个百分点。
- 必要历史配对反事实准确率达到预设目标。
- 无关历史干扰造成的成功率下降不超过预设界限。
- BAR 结构合法率、连续轨迹质量、任务成功率同时达标。
- 恢复率与恢复代价优于匹配基线。

这些是建议的研究门槛，不是当前结果，也不是行业标准；必须根据任务难度、先导实验和统计功效冻结。
