# 06｜安装、资产准备、测试、训练和评测复现

## 1. 解压位置

把发布 ZIP 解压到 XPolicyLab 根目录，使结构成为：

```text
XPolicyLab/policy/KnowAct/README.md
XPolicyLab/policy/KnowAct/G05/src/g05/...
```

不要覆盖 `XPolicyLab/policy/G05/`。如果目标目录已存在，先备份或比较差异。

## 2. Python 环境

vendored G0.5 的 `pyproject.toml` 要求 Python `>=3.10.16,<3.11`，并固定了一组模型/训练依赖（包括 Torch 2.7.1）。正式训练和 benchmark 应使用与该 G0.5 checkout 兼容的 Python 3.10 环境。

V7 本地 CPU 回归曾在 Python 3.13 / Torch 2.10 CPU 环境运行通过，但这不代表官方训练栈兼容 Python 3.13，也不代表 GPU / FlashAttention / FLA / BF16 已验收。

建议分别建立：

- `g05-env`：原版 XPolicyLab G05 baseline。
- `knowact-env`：KnowAct vendored G0.5 + KnowAct Adapter。
- `robodojo-env`：仿真环境客户端依赖（按 XPolicyLab benchmark 文档）。

## 3. 安装

```bash
cd XPolicyLab/policy/KnowAct
export KNOWACT_PYTHON=/path/to/knowact-env/bin/python
bash install.sh
```

`install.sh` 会安装 XPolicyLab 项目和 `KnowAct/G05` editable package。若集群使用已管理的镜像环境，请按该环境的依赖策略安装，不要在已有生产环境中盲目升级 Torch。

## 4. 官方资产

XPolicyLab 的原版 `policy/G05/README.md` 将评测 checkpoint 和训练 base assets 明确分开。仓库为 `OpenGalaxea/g05-robodojo`。

### 官方 RoboDojo FM 评测基线

```bash
mkdir -p /path/to/checkpoints/g05_robodojo_sim
cd /path/to/checkpoints/g05_robodojo_sim

huggingface-cli download OpenGalaxea/g05-robodojo \
  g05_robodojo_fm_only_checkpoint.tar \
  g05_robodojo_fm_only_checkpoint.tar.sha256 \
  --local-dir .

sha256sum -c g05_robodojo_fm_only_checkpoint.tar.sha256
tar -xf g05_robodojo_fm_only_checkpoint.tar

export G05_CKPT_PATH="$PWD/hf_g05_robodojo_fm_only_checkpoint/checkpoints/checkpoint"
export ROBODOJO_G05_ACTION_SOURCE=fm
```

这是官方 RoboDojo simulation 的 FM-only evaluation checkpoint。它是 `compare.py` 默认 G05 baseline；不要强制将它切换为 AR。

### KnowAct 训练 base assets

```bash
mkdir -p /path/to/checkpoints/g05_robodojo_train_assets
cd /path/to/checkpoints/g05_robodojo_train_assets

huggingface-cli download OpenGalaxea/g05-robodojo \
  g05_robodojo_train_base_assets.tar \
  g05_robodojo_train_base_assets.tar.sha256 \
  --local-dir .

sha256sum -c g05_robodojo_train_base_assets.tar.sha256
tar -xf g05_robodojo_train_base_assets.tar
```

解压后：

```text
g05_robodojo_train_base_assets/pretrained/
├── checkpoints/model_state_dict.pt
├── hf_processor/
└── action_tokenizer_hf/
```

训练 base assets 与 FM evaluation checkpoint 不是同一个文件，不能混用。

设置 KnowAct 训练变量：

```bash
export G05_PRETRAINED_CKPT=/path/to/g05_robodojo_train_base_assets/pretrained/checkpoints/model_state_dict.pt
export G05_HF_PROCESSOR_PATH=/path/to/g05_robodojo_train_base_assets/pretrained/hf_processor
export G05_ACTION_TOKENIZER_CKPT=/path/to/g05_robodojo_train_base_assets/pretrained/action_tokenizer_hf/model.safetensors
```

实际 ActionCodec 文件名应以解压目录为准；设置后必须运行 `preflight.py` 并执行真实 encode/decode smoke test。

还需要真实 RoboDojo LeRobot v3 数据集。按照 XPolicyLab 原版 README 使用官方 RoboDojo 数据下载/转换流程；XPolicyLab 根目录的 `scripts/transform_lerobot_v30_format.py` 是对应的 LeRobot v3.0 转换入口。转换完成的目录至少包含：

```text
robodojo_lerobot_v30/
├── meta/
├── data/
└── videos/
```

请先阅读原版 `policy/G05/README.md` 的资产下载、checksum 和许可说明。不要将 RoboDojo simulation FM evaluation checkpoint 误当作 AR 训练 base checkpoint；训练 base assets 与 evaluation checkpoint 是不同资源。

## 6. Preflight

```bash
cd "$XPL_ROOT/policy/KnowAct"
python preflight.py --output results/preflight.json
python preflight.py --require-ready
```

`--require-ready` 检查：

- Python 版本满足 vendored G0.5 的 3.10 约束。
- CUDA 可用。
- XPolicyLab G05 adapter / server 文件存在。
- KnowAct adapter / vendored G05 源码存在。
- checkpoint、processor、ActionCodec 文件或目录存在。
- LeRobot 数据集有 meta/data/videos 子目录。

它不加载 checkpoint，不验证 state dict keys，不读取数据样本，不测试 ActionCodec decode，也不启动 RoboDojo。

在 XPolicyLab 根目录执行：

  -s policy/KnowAct/G05/tests \

本次整理后重新运行的结果为 **73 tests passed**，CPU、无正式权重、测试 fixtures / simulated IO。日志保存在 `results/final_regression_v7_1.log`。如果你在真实环境运行，应保存新的日志，不要覆盖当前发布包的历史记录。

其他静态检查：

```bash
python -m compileall -q policy/KnowAct
bash -n policy/KnowAct/train.sh
bash -n policy/KnowAct/eval.sh
bash -n policy/KnowAct/install.sh
```

## 8. 训练 Smoke Test

```bash
cd "$XPL_ROOT/policy/KnowAct"

export KNOWACT_MAX_STEPS=1000  # 仅 smoke test 示例，不是正式训练预算
export KNOWACT_CONTEXT_TURNS=4
export KNOWACT_REPLAN_STEPS=16
export KNOWACT_BATCH_SIZE=1
export KNOWACT_GRAD_ACCUM=8
export KNOWACT_OUTPUT_ROOT="$PWD/checkpoints"

python preflight.py --require-ready
bash train.sh RoboDojo native arx_x5 joint 11 0
```

参数顺序：

```text
train.sh <benchmark> <experiment/checkpoint-name> <env-config> <action-type> <seed> <gpu-id> [Hydra overrides...]
```

第二个参数是实验/输出名称，不是训练模式。Native KnowAct 默认 `KNOWACT_TRAIN_MODE=ar_only`；训练模式通过环境变量显式设置，非法值会报错。

当前支持 RoboDojo、`arx_x5`、`joint`、Native AR/BAR16。`native` / `ar` 训练模式为 AR-only；Native Context 不支持 FM-only 或 AR+FM 联合模式。

`KNOWACT_MAX_STEPS` 或 `KNOWACT_MAX_EPOCHS` 必须明确设置。正式训练前先跑 1–10 step 的完整 data/model/optimizer smoke test，再增加预算。

## 9. 正式训练对照

先训练单轮和多轮模型：

```bash
# 单轮 BAR16
KNOWACT_CONTEXT_TURNS=1 \
KNOWACT_REPLAN_STEPS=16 \
KNOWACT_MAX_STEPS=10000 \
bash train.sh RoboDojo knowact_single arx_x5 joint 11 0

# 同 Episode Native Context BAR16
KNOWACT_CONTEXT_TURNS=4 \
KNOWACT_REPLAN_STEPS=16 \
KNOWACT_MAX_STEPS=10000 \
bash train.sh RoboDojo knowact_context4 arx_x5 joint 11 0
```

上面的 10,000 步仅为命令示例。正式预算应根据训练数据量、有效监督 Token 数、显存和收敛曲线确定。至少使用多个训练 seeds，并保存完整 resolved config。

注意：当前 Validation DataLoader 仍是单轮 Collate。不要把原验证集 CE 当作多轮上下文验证结果。正式多轮实验前需补充 native validation 数据路径或独立 held-out evaluation。

## 10. RoboDojo 评测

```bash
export KNOWACT_CKPT_PATH=/path/to/knowact/checkpoint

bash eval.sh \
  RoboDojo stack_bowls knowact_context4 arx_x5 joint \
  11 0 0 "$KNOWACT_PYTHON" robodojo
```

参数顺序：

```text
eval.sh <benchmark> <task> <checkpoint-name> <env-config> <action-type> <seed> <policy-gpu> <env-gpu> <policy-python/env> <eval-env>
```

正式比较优先使用 `compare.py`，以统一生成 manifest，避免手工漏掉模型环境变量。

## 11. 生成 benchmark manifest

```bash
python compare.py \
  --task stack_bowls \
  --task cover_blocks \
  --seed 11 --seed 22 --seed 33 \
  --g05-ckpt /path/to/g05_fm_checkpoint \
  --g05-action-source fm \
  --knowact-ckpt /path/to/knowact_checkpoint \
  --g05-env /path/to/g05-env/bin/python \
  --knowact-env "$KNOWACT_PYTHON" \
  --eval-env robodojo \
  --reset-ablation \
  --output comparison_runs/phase1
```

默认 dry-run。检查 `comparison_runs/phase1/manifest.json` 后，添加 `--run` 才启动。
