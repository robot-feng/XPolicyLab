# 05｜XPolicyLab 成对 Benchmark 对比协议

## 1. 当前 compare.py 的职责

`compare.py` 只负责：

1. 生成每个模型 / task / evaluation seed 的 XPolicyLab `eval.sh` 命令。
2. 默认 dry-run，保存 `manifest.json`。
3. `--run` 时顺序启动评测、保存每个 run 的 stdout/stderr 日志和退出码。
4. 对外部导出的 paired episode CSV 计算成功率、相对 G05 的 paired delta 和 task/seed cluster bootstrap 描述区间。

它**不会**自动从 RoboDojo 日志推断 success，也不会替用户生成 episode outcome。

## 2. 一个关键基线问题：官方 RoboDojo G05 是 FM checkpoint

XPolicyLab 的 `policy/G05/README.md` 对官方 RoboDojo simulation checkpoint 的说明使用 `ROBODOJO_G05_ACTION_SOURCE=fm`。G05 Adapter 的 `action_source=auto` 会根据 checkpoint 的 `continuous_action` 配置选择 FM 或 AR。

因此：

- 默认 `--g05-action-source fm`，对应官方 RoboDojo FM-only checkpoint。
- 只有确实使用经过训练和验证的 AR checkpoint 时，才传 `--g05-action-source ar`。
- 不要把 FM-only checkpoint 强制切换为 AR，再将其性能下降解释为 KnowAct 提升。
- G05-MEM 可单独指定 `--g05-memory-action-source` 和 observation offsets。
- KnowAct Native Context 当前固定 AR/BAR16。

G05-FM 与 KnowAct-AR 是实际策略性能比较，但不是只改变 context 的严格架构消融。要归因 Native Context，必须增加相同基座/相同训练设置的 KnowAct-Single 与 KnowAct-Context 对照。

## 3. 运行前需要的 checkpoint

| 参数 | 说明 |
|---|---|
| `--g05-ckpt` | 原版 G05 checkpoint 路径或可解析的 run directory |
| `--knowact-ckpt` | KnowAct BAR16 checkpoint |
| `--g05-memory-ckpt` | 可选的真实 G05-MEM checkpoint |
| `--current-only-ckpt` | 可选的单轮训练 KnowAct checkpoint |
| `--reset-ablation` | 同一 KnowAct checkpoint，但每轮不保留历史 |

G05-MEM 必须同时提供其训练时的 observation offsets；compare 会拒绝缺少 offsets 的配置。

## 4. 成对运行示例

### 4.1 官方 G05-FM vs KnowAct

```bash
cd XPolicyLab/policy/KnowAct

python compare.py \
  --task stack_bowls \
  --task cover_blocks \
  --seed 11 --seed 22 --seed 33 \
  --g05-ckpt /path/to/g05_robodojo_fm_only_checkpoint/checkpoints/checkpoint \
  --g05-action-source fm \
  --knowact-ckpt /path/to/knowact_bar16/checkpoint.pt \
  --g05-env /path/to/g05-env/bin/python \
  --knowact-env /path/to/knowact-env/bin/python \
  --eval-env robodojo \
  --replan-steps 16 \
  --reset-ablation \
  --output comparison_runs/g05fm_vs_knowact
```

默认只生成 manifest 和命令，不会启动仿真。人工检查 manifest、checkpoint、env、GPU 和 task 后，添加 `--run`。

### 4.2 G05-AR vs KnowAct-AR

只有当你有与 G05-AR 对应、确实启用了 discrete action 并经过验证的 checkpoint 时使用：

```bash
--g05-action-source ar
```

### 4.3 加入 G05-MEM 与单轮 KnowAct

```bash
python compare.py \
  --task cover_blocks \
  --seed 11 --seed 22 --seed 33 \
  --g05-ckpt /path/to/g05_fm \
  --g05-action-source fm \
  --g05-memory-ckpt /path/to/g05_mem \
  --g05-memory-action-source fm \
  --g05-memory-offsets=-150,-100,-50,0 \
  --knowact-ckpt /path/to/knowact_context \
  --current-only-ckpt /path/to/knowact_single \
  --g05-env /path/to/g05-env/bin/python \
  --knowact-env /path/to/knowact-env/bin/python \
  --eval-env robodojo \
  --reset-ablation \
  --output comparison_runs/full_ablation
```

G05-MEM 的 offsets 必须与其真实训练配置一致；上面的数值仅为命令格式示例，不是默认推荐配置。

## 5. 执行间隔匹配

- 原版 G05 RoboDojo adapter 默认 `action_steps=16`。
- KnowAct 预测完整32步，但默认 dispatch 前16步。
- `--g05-execution-steps` 默认16。
- `--replan-steps` 默认16。
- 两者不相同时，compare 默认拒绝生成计划；只有显式 `--allow-unmatched-interval` 才允许作为 stress test。

改变执行间隔不仅是 inference 参数变化；如果训练时 `native_replan_steps` 不匹配，就存在训练/部署分布偏移。正式比较应使用匹配 stride 的 checkpoint。

## 6. paired outcome CSV

模板位于 `results/templates/paired_episode_scores.csv`。

必需列：

```csv
task,seed,episode_id,model,success
stack_bowls,11,episode_0001,G05,0
stack_bowls,11,episode_0001,KnowAct,1
```

规则：

- 每个模型必须覆盖相同 `(task, seed, episode_id)` 集合。
- 每个模型/episode 只能出现一次。
- `success` 只能是0或1。
- 必须至少包含 `G05` 和 `KnowAct`。
- 其他模型名称可包括 `KnowAct_reset`、`KnowAct_current`、`G05_MEM`。

统计命令：

```bash
python compare.py --score results/paired_episode_scores.csv
```

输出包括：每个模型成功率、相对 G05 的 paired delta、task/seed cluster 数量、cluster-bootstrap 95% 描述区间。若独立 cluster 少于2，区间返回 null。

## 7. 不要只报告成功率

每个模型和每个任务还应记录：

- 任务成功 / 失败原因。
- 实际执行控制步数、重规划次数、恢复次数。
- 生成延迟 P50 / P95、动作解码延迟、环境 step 时间。
- 峰值 GPU 显存、平均 GPU 利用率。
- 视觉观测数量、上下文 Token 数、上下文长度分布。
- 碰撞、掉落、夹爪失败、错误目标、超时、异常退出。
- action chunk horizon、dispatch stride、实际 receipt steps。

结果模板见 `results/templates/episode_metrics.csv`。

## 8. 公平性检查表

- [ ] 相同 RoboDojo task config / embodiment / control frequency。
- [ ] 相同 task seeds、episode IDs 和初始环境状态。
- [ ] G05 action source 与 checkpoint 配置一致（官方 RoboDojo G05 默认 FM）。
- [ ] KnowAct checkpoint 使用 BAR16 训练布局，不能只在 inference 改 block size。
- [ ] G05-MEM observation offsets 与其训练配置一致。
- [ ] G05 / KnowAct 使用相同执行步长，或明确标记 stress test。
- [ ] 观测相机、图像尺寸、归一化统计一致或明确记录差异。
- [ ] 报告训练数据量、监督 Token 数、优化更新、GPU hours。
- [ ] 所有模型都在同一 episode 集合上评估。
- [ ] 不将模拟 IO 测试、Toy 训练或 dry-run 结果作为 benchmark 成绩。
